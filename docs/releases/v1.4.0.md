# Ada Chat 1.4.0

> Released 2026-10-06 · [Türkçe özet aşağıda](#türkçe-özet)

A small feature release around the first contact with Ada: a public
landing page, invitation e-mails that work as a welcome, an
administration page to reword both in each language, and a default model
for new conversations.

## Highlights

- **Landing page.** Visitors who open Ada before signing in see a short
  public page: the institution's logo or name, a headline and
  introduction, three cards on what Ada offers (many models in one place,
  a monthly budget for everyone, private by design) and a sign-in button.
  Signed-in users still land in the chat. The page shows nothing from the
  database beyond the institution's branding, and sign-in itself stays on
  `/login`.
- **Invitation e-mails that arrive.** Admin → Users → Add users sends each
  new account a welcome ("Your Ada Chat account has been created", with
  the app name from `APP_NAME`), naming who added them and linking to the
  sign-in page. The e-mail is sent unless the option is turned off; a
  version that only sent it when a rebuilt frontend asked for it is fixed.
  An account that has not signed in yet has "Send invitation e-mail" on
  its user page, for people added before invitations existed or whose
  e-mail failed. Addresses that already have an account are skipped, and
  the administrator is told so.
- **Admin → Texts.** Super administrators reword the landing page
  (headline, introduction, the line under the sign-in button, the three
  cards, the footer) and the invitation e-mail (subject, heading, body,
  sign-in note, button) in English and Turkish. Ada's own wording shows
  greyed as the placeholder and stays the default: an empty field keeps
  it. `:app` and `:institution` are filled in automatically, in the e-mail
  also `:name` (the administrator) and `:email`. Changes are audited as
  `content.texts_updated`.
- **Default model.** Admin → Model aliases has a "Default model" choice:
  new conversations start with that alias for everyone whose group may
  use it, ahead of the model the user last picked in their browser. Users
  can still switch in each conversation, and an existing conversation
  keeps its model. "None" (the default after upgrading) keeps the earlier
  behaviour. Audited as `institution.default_model_changed`.

The full list is in the [changelog](../../CHANGELOG.md#140---2026-10-06).

## Requirements

Unchanged from 1.3.1 (see the [1.0.0 notes](v1.0.0.md#requirements)).
Invitation e-mails need a working mailer (`MAIL_MAILER=smtp` and the
`MAIL_*` values), as the budget e-mails already do.

## Upgrading from 1.3.1

1. Take a backup ([deployment guide §5](../deployment.md#5-backups)).
2. Check out the release and follow the usual upgrade steps
   ([guide §8](../deployment.md#8-upgrading)):

   ```bash
   git fetch --tags && git checkout v1.4.0
   ```

   With Docker, `docker compose -f compose.production.yml up -d --build`
   rebuilds the image and runs the migrations on start. Without Docker,
   run `npm ci && npm run build`, then `php artisan migrate --force` and
   `php artisan optimize`. The settings migrations add the `content` group
   (empty: Ada's defaults apply) and an unset default model.
3. Rebuilding the frontend matters this time: the "Add users" dialog and
   the new pages come from it.
4. Open `/` signed out to see the landing page, and Admin → Texts to
   reword it. People added before 1.3.1 who never got an invitation can
   be e-mailed from their user page.
5. Run `php artisan ada:doctor`.

## Known limitations

Unchanged from [1.3.1](v1.3.1.md#known-limitations). The landing page is
shown in the institution's default language (or the browser's, when the
institution has none); there is no language switch on it yet.

## Türkçe özet

Ada Chat 1.4.0, Ada ile ilk karşılaşmayı düzenleyen küçük bir özellik
sürümüdür.

- **Karşılama sayfası:** Giriş yapmadan Ada'yı açan ziyaretçiler kurum
  logosu, bir başlık ve açıklama, Ada'nın sunduklarını anlatan üç kutu ve
  bir giriş düğmesi görür. Giriş yapmış kullanıcılar eskisi gibi doğrudan
  sohbete düşer. Sayfa veritabanından yalnızca kurum markasını alır.
- **Davet e-postası:** Yönetim → Kullanıcılar → "Kullanıcı ekle" ile
  eklenen herkese "Ada Chat hesabınız oluşturuldu" e-postası gider; kimin
  eklediği ve giriş bağlantısı içinde. Yalnızca seçenek kapatılırsa
  gitmez. Henüz giriş yapmamış bir kullanıcının sayfasında "Davet
  e-postası gönder" düğmesi var.
- **Yönetim → Metinler:** Süper yöneticiler karşılama sayfasının ve davet
  e-postasının metinlerini Türkçe ve İngilizce düzenler. Ada'nın kendi
  metni soluk görünür ve varsayılan olarak kalır; boş alan onu korur.
  `:app`, `:institution` (e-postada ayrıca `:name` ve `:email`)
  kendiliğinden dolar.
- **Varsayılan model:** Yönetim → Model takma adları sayfasından herkesin
  yeni sohbetlerinin hangi modelle başlayacağı seçilir (grubu o modeli
  kullanabilenler için). Kullanıcı her sohbette modeli yine değiştirebilir;
  "Yok" seçiliyken (yükseltme sonrası varsayılan) eski davranış sürer.

**1.3.1'den yükseltme:**

1. Yedek alın, `git checkout v1.4.0` ile güncelleyin
   ([rehber §8](../deployment.tr.md#8-güncelleme)).
2. Docker: `docker compose -f compose.production.yml up -d --build`.
   Docker'sız: `npm ci && npm run build`, ardından
   `php artisan migrate --force` ve `php artisan optimize`. Ayar
   migration'ları boş `content` grubunu ve boş varsayılan modeli ekler.
3. Arayüzün yeniden derlenmesi bu sürümde önemli: "Kullanıcı ekle"
   penceresi ve yeni sayfalar oradan gelir.
4. Giriş yapmadan `/` adresini açıp karşılama sayfasını görün; metinleri
   Yönetim → Metinler'den değiştirin.
5. `php artisan ada:doctor` çalıştırın.

**Bilinen sınırlamalar:** 1.3.1 ile aynı. Karşılama sayfası kurumun
varsayılan dilinde gösterilir; üzerinde dil seçici yoktur.
