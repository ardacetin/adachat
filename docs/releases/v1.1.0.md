# Ada Chat 1.1.0

> Released 2026-10-01 · [Türkçe özet aşağıda](#türkçe-özet)

The first feature release after 1.0. It adds an institution-wide spending
cap, CSV exports and a monthly report, a provider for OpenRouter, Ollama,
vLLM and other OpenAI-compatible servers, and file attachments in the chat.
Everything was built in five milestones, each with tests, documentation and
review ([roadmap](../v1-roadmap.md#v11)).

## Highlights

- **Institution-wide monthly cap.** Set the most all users together may
  spend in a month (Admin → Institution). The budget engine enforces it
  as strictly as a user's own limit, even with parallel requests. When
  spending reaches 80 % and 100 % of the cap, Ada e-mails the notification
  addresses. The overview shows how much of the cap has been used.
- **Reports to take away.** "Download CSV" on the reports page gives the
  full breakdown by user, group, provider or model, or the spending per day
  or month, filtered like the page (UTF-8; in Turkish with `;` and decimal
  commas for Excel). After each month the notification addresses get a
  summary e-mail with the per-user and per-day CSV attached.
- **Any OpenAI-compatible server.** A new provider type connects OpenRouter,
  Groq, Ollama, vLLM, LM Studio and other servers that speak the Chat
  Completions API. The API key is optional, for local servers. Self-hosted
  models can be priced at 0: their use is recorded but does not count
  against budgets. Setup examples:
  [provider-architecture.md §9](../provider-architecture.md#9-openai-compatible-servers).
- **Attachments in the chat.** Attach files with the paperclip, by dragging
  or by pasting a screenshot. Each file shows its estimated token cost.
  - Images (PNG, JPEG, WebP, GIF) work with models that support images.
  - PDF, Word, Excel and PowerPoint files (up to 10 MB), and text and code
    files, work with every model.
  - PDFs are sent as the file itself to OpenAI, Anthropic and Gemini models
    with "Files" support, so scanned pages and figures are read too. Other
    models get the text extracted from the PDF.

  Files are checked by their content, kept privately on the server and
  visible only to their owner. They are deleted together with their
  conversation.

The full list is in the [changelog](../../CHANGELOG.md#110---2026-10-01).

## Fixed

- Rate limits on different routes no longer share one counter per user.
  Before, after about ten chat messages in a minute, confirming the usage
  notice ("I understand") answered "Too many requests".

## Requirements

Unchanged from 1.0.0 (see the [1.0.0 notes](v1.0.0.md#requirements)). The PHP
extensions used for attachments (`fileinfo`, `zip`, `iconv`) are part of the
standard PHP build and of the Docker image.

Optional:

- An SMTP server for cap alerts and the monthly report.
- An OpenAI-compatible server for local models.

## Upgrading from 1.0.0

1. Take a backup ([deployment guide §5](../deployment.md#5-backups)).
2. Check out the release and follow the usual upgrade steps
   ([guide §8](../deployment.md#8-upgrading)):

   ```bash
   git fetch --tags && git checkout v1.1.0
   ```

   With Docker, `docker compose -f compose.production.yml up -d --build`
   rebuilds the image and runs the migrations on start. The migrations
   add the institution periods and the attachments table, and allow the
   new provider type.
3. **Request size limits.** Attachments need bodies of up to 12 MB.
   - The Docker image already has the new limits.
   - Update them yourself in the host nginx in front of Docker
     ([`deploy/nginx/ada-docker-proxy.conf`](../../deploy/nginx/ada-docker-proxy.conf))
     and on installations without Docker:
     - nginx: `client_max_body_size 12m;`
     - PHP-FPM: `upload_max_filesize = 11M`, `post_max_size = 12M`
   - Then reload nginx and PHP-FPM.
4. **E-mail.** Set the `MAIL_*` values in `.env`
   (see [`deploy/env.production.example`](../../deploy/env.production.example)).
   Then, under Admin → Institution:
   - enter the notification addresses and, if you want, a monthly cap;
   - press "Send a test e-mail".
5. **Attachments.** In Admin → Models, turn on "Images" and "Files" for the
   models that support them. Optional `.env` limits:
   `ADA_ATTACHMENT_MAX_IMAGE_MB` (5), `ADA_ATTACHMENT_MAX_TEXT_MB` (1),
   `ADA_ATTACHMENT_MAX_DOCUMENT_MB` (10).
6. Make sure the scheduler runs. It now also sends cap alerts (every five
   minutes) and the monthly report.
7. Run `php artisan ada:doctor`.

## Known limitations

- One institution per installation. Sign-in only through Google Workspace
  SAML; other identity providers are planned.
- No public API yet. An OpenAI-compatible API with personal tokens is
  planned.
- Conversation content and attached files are stored unencrypted, in the
  database and in `storage/app/private`. Anyone with server or backup
  access can read them; protect them accordingly
  ([security.md](../security.md)).
- No OCR, and no legacy Office formats (.doc, .xls, .ppt). A scanned PDF
  can only be used with a model that reads PDF files.
- Attachments are sent to the provider again with every message while they
  are part of the conversation, so long conversations with files cost
  more. Each file's estimated token cost is shown when it is attached.
- No web search, tools or agents.

## Türkçe özet

Ada Chat 1.1.0, 1.0'dan sonraki ilk özellik sürümüdür.

- **Kurum geneli aylık harcama tavanı:** Tüm kullanıcıların bir ayda
  birlikte harcayabileceği en yüksek tutar (Yönetim → Kurum). Bütçe
  motoru bu tavanı paralel isteklerde bile aşılmaz şekilde uygular.
  Tavanın %80'ine ve %100'üne gelindiğinde bildirim adreslerine e-posta
  gider.
- **CSV dışa aktarma ve aylık rapor:**
  - Raporlar sayfasında "CSV indir": kullanıcı, grup, sağlayıcı ya da
    modele göre tam döküm ve günlük/aylık harcama. Türkçe Excel uyumludur
    (`;` ayraç, ondalık virgül).
  - Her ay sonunda bildirim adreslerine CSV ekli bir özet e-postası gider.
- **OpenAI uyumlu sunucular:** OpenRouter, Groq, Ollama, vLLM, LM Studio.
  API anahtarı isteğe bağlıdır. Kendi sunucunuzdaki modellere fiyat
  olarak 0 girilebilir; kullanım kaydedilir ama bütçeden düşmez.
- **Sohbette ekler:** Görsel (görsel destekli modellerde); PDF, Word,
  Excel ve PowerPoint (en çok 10 MB); metin ve kod dosyaları.
  - PDF'ler "Dosyalar" desteği olan OpenAI, Anthropic ve Gemini
    modellerine dosyanın kendisi olarak gider. Diğer modellere PDF'nin
    metni gider.
  - Dosyalar içeriğine göre denetlenir, yalnızca sahibine görünür ve
    sohbetle birlikte silinir.
- **Düzeltme:** İstek sınırları artık kullanıcı başına tek bir sayacı
  paylaşmıyor. Önceden çok mesaj gönderen kullanıcı kullanım bildirimini
  onaylayamayabiliyordu.

**1.0.0'dan yükseltme:**

1. Yedek alın.
2. `git checkout v1.1.0` ile güncelleyin
   ([rehber §8](../deployment.tr.md#8-güncelleme)).
3. Docker önündeki nginx'te ve Docker'sız kurulumlarda gövde sınırlarını
   büyütün:
   - nginx: `client_max_body_size 12m;`
   - PHP: `upload_max_filesize = 11M`, `post_max_size = 12M`
4. `.env` dosyasına `MAIL_*` ayarlarını girin. Ardından Yönetim → Kurum'da
   bildirim adreslerini girin ve test e-postası gönderin.
5. Görsel ve PDF desteği olan modellerde "Görseller" ve "Dosyalar"
   yeteneklerini açın.
6. Zamanlayıcının çalıştığını doğrulayın ve `php artisan ada:doctor`
   çalıştırın.

**Bilinen sınırlamalar:**

- Kurulum başına tek kurum; giriş yalnızca Google Workspace SAML ile.
- Henüz dış API yok.
- Sohbet içerikleri ve ekler sunucuda şifresiz durur.
- OCR ve eski Office biçimleri (.doc, .xls, .ppt) yok.
- Ekler, sohbette kaldıkça her mesajla yeniden gönderilir.
