# Ada Chat 2.0.0

> Released 2026-10-07 · [Türkçe özet aşağıda](#türkçe-özet)

Version 2.0 adds two features for institutions: groups that follow the
identity provider, and protection of personal data before it reaches an AI
provider. Upgrading from 1.5 changes nothing until an administrator turns
them on.

## Highlights

- **Group mapping from the identity provider.** Ada can put each user in a
  group from the groups their identity provider sends at sign-in, so group
  membership is managed where people already are (Entra ID, Google
  Workspace, Keycloak) instead of by hand.
  - Each group (Administration → Groups) lists the provider's groups: names
    or IDs (Entra ID: group object IDs), one per line. A *mapping priority*
    decides for people in several.
  - At each sign-in the user is moved to the matching group; the change is
    in the audit log and the new group's budget applies to the current
    month.
  - Users in none of the mapped groups keep their group, go to the default
    group, or cannot sign in, as set under Administration → Sign-in.
    Administrators are never refused, so a mapping mistake cannot lock them
    out.
  - A group an administrator sets by hand while mapping is on is pinned.
    The user's page shows where the group comes from and the values the
    provider sent at the last sign-in.
  - Roles are not mapped; administrators are still made in Ada.
- **Personal data protection.** Administration → Personal data checks
  messages, and the text of their attachments, for personal data before
  they are sent to a provider.
  - Built-in checks: Turkish identity numbers, IBANs and card numbers
    (only with valid check digits, so ordinary numbers are rarely
    mistaken), Turkish phone numbers and e-mail addresses. Institutions can
    add up to 20 patterns of their own, such as student numbers.
  - For each kind: **warn** (the user can edit the message or send it
    anyway), **mask** (a placeholder such as `[TCKN_1]` is sent and the
    answer shows the real value) or **block**.
  - A refused message is not stored or charged. Messages note which kinds
    were hidden; values are never shown, stored or logged by this feature.
  - **Try it** on the page shows what a sample text would look like when
    sent.

## Behaviour changes

None while both features are off, which is the default.

- With group mapping on, a sign-in can move a user to another group, and
  with *Do not let them sign in* users outside the mapped groups are
  refused (`no_mapped_group`).
- With any personal data kind masked, PDFs are sent as their extracted
  text instead of as files, so their text can be masked too. Scanned PDFs
  without text are then not sent.

- The build tooling is updated to `vite-plus` 1.0 (Vitest 5, Oxlint 1.85,
  Oxfmt 0.70); the built application behaves the same.

## Upgrading from 1.5.0

1. Take a backup ([deployment guide §5](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#5-backups)).
2. Check out the release and follow the usual upgrade steps
   ([guide §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#8-upgrading)):

   ```bash
   git fetch --tags && git checkout v2.0.0
   ```

   With Docker, `docker compose -f compose.production.yml up -d --build`.
   Without Docker, run `npm ci && npm run build`, then
   `php artisan migrate --force` and `php artisan optimize`.
3. The migrations add two columns to `groups` and one to `users` (quick),
   and the settings for both features, switched off.
4. To use group mapping
   ([authentication guide §1b](https://github.com/ardacetin/adachat/blob/main/docs/authentication.md#1b-group-mapping)):
   - Have the identity provider send the groups and set
     `SAML_ATTRIBUTE_GROUPS` or `OIDC_GROUPS_CLAIM` in `.env`; run
     `php artisan config:cache` if you use it.
   - Sign in once as a test user and copy the values from their page
     (Administration → Users) into the groups.
   - Turn it on under Administration → Sign-in.
5. To use personal data protection, choose the actions under
   Administration → Personal data and try them with a sample text
   ([docs/personal-data.md](https://github.com/ardacetin/adachat/blob/main/docs/personal-data.md)).
6. Run `php artisan ada:doctor`.

## Known limitations

Unchanged from [1.5.0](https://github.com/ardacetin/adachat/blob/main/docs/releases/v1.5.0.md#known-limitations). In addition:

- Group mapping: Entra ID sends at most 200 groups in a token. With more,
  it leaves them out and Ada changes nothing for that sign-in; assigning
  only the needed groups to the application avoids it. Roles are not
  mapped.
- Personal data protection is pattern based: it finds the formats above,
  not names, addresses or descriptions of people, and it does not check
  images. It is a safety net; the usage notice should still tell users
  what not to share.
- Shared links and Markdown exports contain the stored text, with the real
  values.

## Türkçe özet

Ada Chat 2.0, kurumlar için iki özellik getiriyor. 1.5'ten yükseltmek, bir
yönetici açana kadar hiçbir şeyi değiştirmez.

- **Kimlik sağlayıcısından grup eşleme.** Kullanıcılar girişte, kimlik
  sağlayıcısının (Entra ID, Google Workspace, Keycloak) gönderdiği gruplara
  göre bir Ada grubuna yerleştirilir. Her grupta sağlayıcının grup adları
  veya kimlikleri listelenir; birden fazla eşleşmede öncelik sayısı karar
  verir. Grup değişikliği denetim kaydına yazılır ve yeni grubun bütçesi bu
  aya uygulanır. Eşleşmeyenler grubunda kalır, varsayılan gruba alınır ya da
  giriş yapamaz (Yönetim → Giriş). Yöneticiler hiçbir zaman reddedilmez.
  Eşleme açıkken elle atanan grup sabitlenir; kullanıcı sayfasında son
  girişte gelen değerler görünür. Roller eşlenmez.
- **Kişisel veri koruması.** Yönetim → Kişisel veriler, mesajları ve
  eklerinin metnini sağlayıcıya gitmeden önce tarar: T.C. kimlik no, IBAN,
  kart numarası (yalnızca doğrulama haneleri doğruysa), Türkiye telefon
  numaraları, e-posta adresleri ve kurumun tanımladığı en fazla 20 kalıp
  (örneğin öğrenci numarası). Her tür için: **uyar** (kullanıcı düzenler ya
  da yine de gönderir), **maskele** (`[TCKN_1]` gibi bir yer tutucu gider,
  yanıtta gerçek değer gösterilir) veya **engelle**. Reddedilen mesaj
  kaydedilmez ve ücretlendirilmez; değerler hiçbir yerde gösterilmez,
  saklanmaz, günlüğe yazılmaz. Sayfadaki deneme kutusuyla örnek bir metin
  denenebilir.

**1.5.0'dan yükseltme:** Yedek alın, `git checkout v2.0.0` ile güncelleyin
([rehber §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.tr.md#8-güncelleme)).
Migration'lar `groups` tablosuna iki, `users` tablosuna bir kolon ve iki
özelliğin (kapalı) ayarlarını ekler. Grup eşleme için `.env`'de
`SAML_ATTRIBUTE_GROUPS` veya `OIDC_GROUPS_CLAIM` ayarlayın, bir test
kullanıcısıyla giriş yapıp sayfasındaki değerleri gruplara girin ve
Yönetim → Giriş'ten açın. Kişisel veri koruması için Yönetim → Kişisel
veriler'den işlemleri seçin. Ardından `php artisan ada:doctor` çalıştırın.

**Bilinen sınırlamalar:** Entra ID bir token'da en fazla 200 grup gönderir;
fazlasında o girişte grup değişmez. Kişisel veri koruması kalıp tabanlıdır;
isim, adres gibi bilgileri ve görselleri kontrol etmez. Paylaşım
bağlantıları ve dışa aktarımlar gerçek değerleri içerir.
