# Ada Chat 1.3.1

> Released 2026-10-05 · [Türkçe özet aşağıda](#türkçe-özet)

A security release. An audit of the whole system with Cloudflare's
[security audit skill](https://github.com/cloudflare/security-audit-skill)
(standard profile) found four issues, and two more that depend on how an
installation is run. All six are fixed. The release also adds invitation
e-mails for users added by an administrator.

**Every installation should upgrade.** Docker installations must also
change one line in the host nginx configuration (step 3 below).

## Security fixes

- **Stopped answers were charged almost nothing** (medium).
  - Before: an answer stopped with the Stop button or by closing the page
    was charged only the usage the provider had reported when the answer
    began (for Anthropic, about one output token), although the text had
    been delivered. Stopping just before the end gave long answers outside
    the budget.
  - Now: such answers are charged at least an estimate of the text and
    reasoning delivered, within the message's output limit.
- **A crafted spreadsheet could exhaust the server** (medium).
  - Before: a small .xlsx file could make text extraction use memory and
    CPU far beyond its size, with a cell reference such as `ZZZZZZZ1`, or
    one worksheet listed thousands of times.
  - Now: spreadsheets are read within fixed bounds: at most 100 sheets,
    each sheet once, columns up to Excel's last column (`XFD`), and no more
    text than Ada keeps.
- **SAML sign-in could be completed in another browser** (low, login CSRF).
  - Before: someone could start a sign-in, sign in at Google and have
    another person's browser finish it, signing that browser into their
    account.
  - Now: a sign-in only completes in the browser that started it (a
    short-lived `ada_saml_binding` cookie). Ada must be served over HTTPS,
    as the deployment guide already requires.
- **Clients could choose the IP address in the audit log** (low, Docker).
  - Before: with the Docker default `TRUSTED_PROXIES=*`, a client could set
    the IP address recorded in the audit log and used by per-IP rate
    limits by sending its own `X-Forwarded-For` header.
  - Now: `*` trusts only the proxy directly in front of Ada, and the
    shipped nginx file replaces the header the client sent.
- **A running answer could be charged only an estimate.** The cleanup job
  that settles answers of crashed processes could also settle an answer
  still being delivered to a slow client; its real usage was then lost.
  The rest is now charged when the answer ends, and a provider that
  delivers data very slowly can no longer hold an answer past its time
  limit.
- **With SAML, an account belonged to the e-mail address.** If the
  institution gives a former employee's address to someone else, that
  person signed into the old account (role, budget, conversations) unless
  it had been disabled. A new setting, `SAML_ATTRIBUTE_SUBJECT`, ties
  accounts to an identifier that is never reused (step 4 below).

Details: [CHANGELOG](https://github.com/ardacetin/adachat/blob/main/CHANGELOG.md#131---2026-10-05) and
[security.md](https://github.com/ardacetin/adachat/blob/main/docs/security.md).

## New

- **Invitation e-mails.** Admin → Users → Add users can e-mail each new
  account, in the institution's language, with a link to the sign-in page
  (on by default). The e-mail contains no password or token: people still
  sign in with the institution's identity provider. If an e-mail cannot be
  sent, the account is still created and the administrator sees a warning.

## Upgrading from 1.3.0

There are no database migrations.

1. Take a backup ([deployment guide §5](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#5-backups)).
2. Check out the release and follow the usual upgrade steps
   ([guide §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#8-upgrading)):

   ```bash
   git fetch --tags && git checkout v1.3.1
   ```

   With Docker: `docker compose -f compose.production.yml up -d --build`.
3. **Docker installations: update the host nginx configuration.** In the
   file based on
   [`deploy/nginx/ada-docker-proxy.conf`](https://github.com/ardacetin/adachat/blob/main/deploy/nginx/ada-docker-proxy.conf),
   replace

   ```nginx
   proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
   ```

   with

   ```nginx
   proxy_set_header X-Forwarded-For $remote_addr;
   ```

   then run `sudo nginx -t && sudo systemctl reload nginx`.
4. **SAML: set a stable identifier (recommended).**
   - First, disable in Admin → Users the Ada accounts of people who have
     left. Until each account signs in once with the identifier, it is
     still found by its e-mail address.
   - Send an identifier that is never reused as an attribute of the SAML
     app, for example *Employee details → Employee ID* in Google Admin, or
     `user.objectid` in Microsoft Entra ID.
   - Set its name in `.env`, for example `SAML_ATTRIBUTE_SUBJECT=employee_id`.
   - Every user must have the attribute: responses without it are refused.

   `ada:doctor` warns while this is not set. Until then, disable the Ada
   account of everyone who leaves before their address can be reused
   ([authentication.md](https://github.com/ardacetin/adachat/blob/main/docs/authentication.md#account-linking-and-provisioning)).
5. **E-mail.** Invitation and budget e-mails need a working mailer:
   `MAIL_MAILER=smtp` with the `MAIL_*` values. With `MAIL_MAILER=log`
   e-mails are only written to the log. Use Admin → Institution → "Send a
   test e-mail" to check.
6. Run `php artisan ada:doctor`.

## Known limitations

Unchanged from [1.3.0](https://github.com/ardacetin/adachat/blob/main/docs/releases/v1.3.0.md#known-limitations). In addition: while an
answer is held by a client that reads very slowly, the user may start one
more answer than their concurrency limit allows; it is charged in full.

## Türkçe özet

Ada Chat 1.3.1 bir güvenlik sürümüdür. Cloudflare'in güvenlik denetimi
aracıyla yapılan tam denetimde bulunan altı sorun düzeltildi. **Bütün
kurulumların güncellemesi önerilir.**

**Güvenlik düzeltmeleri:**

- Durdurulan yanıtlar artık iletilen metin kadar bütçeden düşülüyor.
  Önceden neredeyse hiç ücretlendirilmiyordu.
- Özel hazırlanmış küçük bir .xlsx dosyası sunucuyu yoramıyor; tablolar
  sabit sınırlar içinde okunuyor.
- SAML girişi yalnızca başlatıldığı tarayıcıda tamamlanabiliyor.
- Docker'da istemciler denetim kaydındaki IP adresini artık
  belirleyemiyor.
- Yavaş okuyan bir istemciye giden yanıtın gerçek kullanımı artık kaybolmuyor.
- SAML hesapları isteğe bağlı olarak e-posta yerine hiç değişmeyen bir
  kimliğe bağlanabiliyor (`SAML_ATTRIBUTE_SUBJECT`).

**Yeni:** Yönetim → Kullanıcılar → "Kullanıcı ekle" ile eklenen kişilere
kurumun dilinde davet e-postası gidiyor (varsayılan açık).

**1.3.0'dan yükseltme** (veritabanı değişikliği yok):

1. Yedek alın, `git checkout v1.3.1` ile güncelleyin
   ([rehber §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.tr.md#8-güncelleme)).
2. **Docker kurulumları:** sunucudaki nginx dosyasında
   `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` satırını
   `proxy_set_header X-Forwarded-For $remote_addr;` ile değiştirip nginx'i
   yeniden yükleyin.
3. **SAML (önerilir):**
   - Önce ayrılan kişilerin Ada hesaplarını devre dışı bırakın.
   - SAML uygulamasında hiç yeniden kullanılmayan bir kimlik gönderin;
     örneğin Google Admin'de *Employee details → Employee ID*.
   - `.env`'e adını yazın, örneğin `SAML_ATTRIBUTE_SUBJECT=employee_id`.
4. **E-posta:** davet ve bütçe e-postaları için `MAIL_MAILER=smtp` ve
   `MAIL_*` ayarları gerekir. `MAIL_MAILER=log` iken e-postalar yalnızca
   log'a yazılır. Yönetim → Kurum'daki test e-postasıyla deneyin.
5. `php artisan ada:doctor` çalıştırın.
