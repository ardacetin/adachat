# Ada Chat 1.2.0

> Released 2026-10-02 · [Türkçe özet aşağıda](#türkçe-özet)

The second feature release, planned with the first pilot's feedback. It
makes adding a model a matter of picking it from a price catalog, adds
sign-in with Microsoft Entra ID and other OpenID Connect providers, lets
administrators decide by e-mail address who may sign in, brings search,
pinning and export to the chat, and introduces institutional assistants
with their own instructions and documents. Everything was built in five
steps, each with tests, documentation and review
([roadmap](https://github.com/ardacetin/adachat/blob/main/docs/v1-roadmap.md#v12)).

## Highlights

- **Easy model pricing.** In Admin → Models, choose a model from Ada's
  price catalog instead of typing four prices. The catalog
  (`resources/catalog/models.json`) holds the providers' official prices
  with their source and date, including price changes they have announced.
  - The former form is still there as "Advanced", for models outside the
    catalog and for OpenAI-compatible servers ("Free (self-hosted model)"
    sets every price to 0).
  - When a release updates catalog prices, the model list and
    `ada:doctor` point out the models concerned; "Use new prices" takes
    them over (audited).
  - `ADA_MODEL_CATALOG` points Ada to an institution's own copy.
- **Sign-in with Microsoft Entra ID and OpenID Connect**, next to or
  instead of Google Workspace SAML.
  - The Entra ID preset needs a single-tenant issuer, checks the tenant
    of every sign-in and refuses guest accounts.
  - A generic mode works with Keycloak, Okta and other providers; it
    requires `email_verified`.
  - Authorization code flow with PKCE; ID tokens are verified against the
    provider's published keys (RS256/ES256 only).
  - Configured in `.env`. Administration → Sign-in shows the redirect URI
    and tests the connection; `ada:doctor` checks it too. Step by step:
    [authentication.md §1a](https://github.com/ardacetin/adachat/blob/main/docs/authentication.md#1a-openid-connect-microsoft-entra-id-generic).
- **Who may sign in, by e-mail address.** Administration → Users → Add
  users takes a list of addresses with a group and a role. The list shows
  who has not signed in yet; unused invitations can be removed.
  - Added addresses can sign in even outside the allowed domains (the
    address must still be verified by the identity provider).
  - Turn off "Anyone with an address in an allowed domain can sign in" to
    let only listed users in.
  - Each row of the users list now has a menu to disable or enable the
    account and, for super administrators, to change the role.
- **Chat: search, pin, export.**
  - Search your own conversations by title, message text or file name
    (Ctrl+K / ⌘K). Nobody else's conversations are searched, also not by
    administrators.
  - Pin conversations to keep them at the top of the sidebar.
  - Download a conversation as Markdown, or print it / save it as PDF.
- **Institutional assistants.** Super administrators define assistants
  under Administration → Assistants
  ([docs/assistants.md](https://github.com/ardacetin/adachat/blob/main/docs/assistants.md)):
  - instructions on top of a model alias (the alias's own system prompt
    comes first), the groups that may use it, an icon and up to four
    starter prompts;
  - fixed documents (PDF, Word, Excel, PowerPoint, text and code) whose
    text is sent with the instructions, up to 50,000 tokens per assistant
    by default and never more than half the model's context window. The
    form shows the tokens and the estimated cost they add to every message.

  Users open assistants from the Assistants gallery; the conversation
  keeps the assistant's model. With Anthropic models the instructions and
  documents are cached by the provider, so repeated messages cost less.

The full list is in the [changelog](https://github.com/ardacetin/adachat/blob/main/CHANGELOG.md#120---2026-10-02).

## Requirements

Unchanged from 1.1.0 (see the [1.0.0 notes](https://github.com/ardacetin/adachat/blob/main/docs/releases/v1.0.0.md#requirements)).

Optional:

- A Microsoft Entra ID app registration, or another OpenID Connect
  provider, for OIDC sign-in. The server must reach the provider's
  discovery and key URLs over HTTPS.

## Upgrading from 1.1.0

1. Take a backup ([deployment guide §5](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#5-backups)).
2. Check out the release and follow the usual upgrade steps
   ([guide §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#8-upgrading)):

   ```bash
   git fetch --tags && git checkout v1.2.0
   ```

   With Docker, `docker compose -f compose.production.yml up -d --build`
   rebuilds the image and runs the migrations on start. Without Docker,
   run `php artisan migrate --force`. The migrations add:
   - invitations to the users table;
   - pinning to conversations;
   - the assistants, their groups and their documents.
3. **Models.** Existing models keep their prices and appear as
   "Advanced". Nothing has to change. To follow the catalog, edit a model
   and choose it in the "Easy: prices from the catalog" mode.
4. **Prompt caching.** Check that Anthropic models have a "Cache write"
   price (catalog models do). Assistants with documents write to the cache
   on the first message, and Ada charges that price for it.
5. **OIDC (optional).** Register `${APP_URL}/auth/oidc/callback` as the
   redirect URI with your provider, then set in `.env`:

   ```dotenv
   OIDC_ENABLED=true
   OIDC_PRESET=entra
   OIDC_ISSUER=https://login.microsoftonline.com/<tenant ID>/v2.0
   OIDC_CLIENT_ID=…
   OIDC_CLIENT_SECRET=…
   OIDC_LABEL=Microsoft
   ```

   Then press "Test connection" under Administration → Sign-in.
6. **Who may sign in.** Review Administration → Sign-in. If only listed
   people should get in, turn off "Anyone with an address in an allowed
   domain can sign in" and add them under Administration → Users.
7. Optional `.env` limit: `ADA_ASSISTANT_MAX_DOCUMENT_TOKENS` (50000).
8. Run `php artisan ada:doctor`.

## Known limitations

- One institution per installation.
- An account found by e-mail is linked to a second sign-in provider only
  if it has no identity from that provider yet
  ([authentication.md](https://github.com/ardacetin/adachat/blob/main/docs/authentication.md#account-linking-and-provisioning)).
- No public API yet. An OpenAI-compatible API with personal tokens is
  planned.
- Conversation content, attached files and assistant documents are stored
  unencrypted, in the database and in `storage/app/private`. Anyone with
  server or backup access can read them; protect them accordingly
  ([security.md](https://github.com/ardacetin/adachat/blob/main/docs/security.md)).
- Assistant documents are sent in full with every message; there is no
  search over large document collections (RAG). PDFs are sent as their
  extracted text, so scanned PDFs cannot be used as assistant documents.
- Prompt caching applies to Anthropic models; OpenAI caches long prompts
  on its own, Gemini and OpenAI-compatible servers are sent the documents
  uncached.
- Search uses simple matching (no stemming or ranking), which suits the
  size of one person's conversation history.
- No OCR, no legacy Office formats (.doc, .xls, .ppt), no web search,
  tools or agents.

Candidates for the next versions are listed in the
[roadmap](https://github.com/ardacetin/adachat/blob/main/docs/v1-roadmap.md#candidates-for-v2).

## Security

Report vulnerabilities privately as described in
[SECURITY.md](https://github.com/ardacetin/adachat/blob/main/SECURITY.md). How OIDC sign-in is protected (PKCE,
single-use state and nonce, signature and claim checks, tenant pinning)
is described in [authentication.md](https://github.com/ardacetin/adachat/blob/main/docs/authentication.md#1a-openid-connect-microsoft-entra-id-generic).

## Türkçe özet

Ada Chat 1.2.0, ilk pilotun geri bildirimiyle planlanan ikinci özellik
sürümüdür.

- **Kolay model fiyatlandırması:** Yönetim → Modeller'de model, fiyat
  yazmadan Ada'nın fiyat kataloğundan seçilir. Katalog, sağlayıcıların
  resmî fiyatlarını kaynak ve tarihleriyle tutar. Eski form "Gelişmiş"
  modda duruyor. Yeni bir sürüm fiyatları güncellerse model listesi ve
  `ada:doctor` ilgili modelleri gösterir; "Yeni fiyatları kullan" ile
  güncellenir.
- **Microsoft Entra ID ve OpenID Connect ile giriş:** Google SAML'in
  yanında ya da yerine.
  - Entra hazır ayarı tek kiracıyla çalışır, kiracıyı denetler ve konuk
    hesapları reddeder.
  - Keycloak, Okta gibi sağlayıcılar için genel mod vardır.
  - Ayarlar `.env` dosyasındadır. Yönetim → Giriş ekranı yönlendirme
    adresini gösterir ve bağlantıyı test eder.
- **Kimin girebileceği e-posta adresiyle:** Yönetim → Kullanıcılar →
  Kullanıcı ekle. Eklenen adresler izinli alan adı dışında olsa da
  girebilir. "İzinli bir alan adında adresi olan herkes giriş yapabilir"
  kapatılırsa yalnızca
  listedekiler girer. Kullanıcı satırındaki menüden hesap pasifleştirilir
  ya da etkinleştirilir; süper yönetici rolü de değiştirebilir.
- **Sohbette arama, sabitleme, dışa aktarma:**
  - Kendi sohbetlerinizde başlık, mesaj ve dosya adına göre arama
    (Ctrl+K / ⌘K). Yöneticiler başkalarının sohbetlerinde arama yapamaz.
  - Sohbetleri kenar çubuğunun üstüne sabitleme.
  - Markdown indirme ve yazdırma / PDF olarak kaydetme.
- **Kurum içi asistanlar:** Süper yönetici bir model takma adı üzerine
  talimat, gruplar, simge ve başlangıç önerileri tanımlar; sabit belgeler
  (PDF, Office, metin) ekleyebilir. Belgelerin metni her mesajla gider
  (varsayılan en çok 50 000 token). Form, mesaj başına token ve maliyeti
  gösterir. Anthropic modellerinde talimat ve belgeler önbelleğe alınır.
  Kullanıcılar asistanları Asistanlar galerisinden açar.

**1.1.0'dan yükseltme:**

1. Yedek alın.
2. `git checkout v1.2.0` ile güncelleyin
   ([rehber §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.tr.md#8-güncelleme)). Docker kendisi
   migration çalıştırır; Docker'sız kurulumda
   `php artisan migrate --force` çalıştırın.
3. Mevcut modeller fiyatlarını korur ve "Gelişmiş" olarak görünür;
   değişiklik gerekmez.
4. Anthropic modellerinde "Önbelleğe yazma" fiyatının girili olduğunu
   kontrol edin (katalog modellerinde girilidir).
5. İsterseniz OIDC: sağlayıcıya `${APP_URL}/auth/oidc/callback`
   yönlendirme adresini kaydedin, `.env` dosyasına `OIDC_*` değerlerini
   girin, Yönetim → Giriş'te bağlantıyı test edin.
6. Yönetim → Giriş'te kimlerin girebileceğini gözden geçirin.
7. `php artisan ada:doctor` çalıştırın.

**Bilinen sınırlamalar:**

- Kurulum başına tek kurum; henüz dış API yok.
- Sohbetler, ekler ve asistan belgeleri sunucuda şifresiz durur.
- Asistan belgeleri her mesajla bütünüyle gönderilir; büyük belge
  arşivlerinde arama (RAG) yok. Taranmış PDF'ler asistan belgesi olarak
  kullanılamaz.
- OCR, eski Office biçimleri, web araması ve araçlar yok.
