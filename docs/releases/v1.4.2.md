# Ada Chat 1.4.2

> Released 2026-10-06 · [Türkçe özet aşağıda](#türkçe-özet)

A security release. A full security audit with the
[Cloudflare security-audit skill](https://github.com/cloudflare/security-audit-skill)
confirmed one medium and three low findings, and raised three leads that
depend on provider behaviour. All are fixed, with tests. The audit's
hardening notes are applied too. **Every installation should upgrade**,
above all those that offer both SAML and OIDC sign-in.

## Security fixes

### Medium

- **A reused e-mail address could open the previous holder's account
  through the other sign-in method.**
  - Before: with SAML and OIDC both enabled, a sign-in at the provider an
    account had not used yet was linked to it by e-mail address alone. If
    the institution had given the address to someone else and the old
    account was still active, the new holder got that account, with its
    role, budget and conversations. This bypassed the protection a stable
    identifier (`SAML_ATTRIBUTE_SUBJECT`, the OIDC `sub`) gives.
  - Now: an account is linked by e-mail address only while no stable
    identifier claims it: added by an administrator and never signed in,
    or known only by e-mail-keyed SAML identities. Otherwise the sign-in
    gets `account_conflict` and an administrator resolves it. A disabled
    account is never linked to a new sign-in method.

### Low

- **The `.env` API key could be sent to an address chosen in the panel.** A
  provider created with a different base URL and no key of its own used
  the `.env` key there. The `.env` key now goes only to the driver's own
  address; such a provider needs its own key.
- **Administrators could raise their own budget through their group.** A
  group that contains the administrator, or a super administrator, can
  now be changed only by super administrators. The form says so.
- **Sharing had no limits.** Every link and every copy stores the
  conversation again. Now:
  - at most 10 live links per conversation (`ADA_SHARE_MAX_LINKS`);
  - at most 50 links and copies together per user per day
    (`ADA_SHARE_DAILY_LIMIT`);
  - revoking a link deletes its stored copy;
  - copies are recorded in the audit log.

### Charging and availability

These depend on how a provider tokenizes and bills, which the audit could
not observe. They are fixed anyway:

- A stopped or cut-off answer of a Gemini or OpenAI-compatible reasoning
  model paid only for the text it showed, not the reasoning the provider
  bills. It is now charged up to the message's output limit, as OpenAI's
  already was.
- An answer with no usage report (stopped on an OpenAI-compatible server)
  paid its estimated input without the safety margin. It now pays the
  input as reserved.
- A provider that sends its headers very slowly could hold a request, and
  a PHP worker, past the time limit. PHP-FPM now ends any request after
  420 seconds.

## Hardening

- Provider requests no longer follow redirects, which could carry the
  Anthropic or Gemini key to another host. A redirect shows as an error,
  so a wrong base URL is noticed.
- Oversized provider stream lines (over 1 MiB) and events (over 4 MiB) end
  the answer; error bodies are read up to 64 KiB; negative usage values
  count as zero.
- `X-Forwarded-Prefix` is no longer believed from a proxy, and the Docker
  proxy file clears it.
- Links shared by a disabled user stop working until the account is
  enabled again.
- Names in the invitation e-mail can no longer turn into links.
- CSV exports also defuse the header row and keep negative amounts as
  numbers.

Details: [CHANGELOG](https://github.com/ardacetin/adachat/blob/main/CHANGELOG.md#142---2026-10-06).

## Behaviour changes

- **Sign-in with two providers.** A person whose account is bound to one
  provider's stable identifier (OIDC, or SAML with
  `SAML_ATTRIBUTE_SUBJECT`) and who signs in with the other provider for
  the first time gets `account_conflict`. Moving from Google SAML without
  an identifier attribute to Entra ID still links automatically
  ([authentication guide](https://github.com/ardacetin/adachat/blob/main/docs/authentication.md)).
- **Groups.** Administrators cannot change the default group if a super
  administrator is in it. Move super administrators to their own group,
  or let a super administrator make the change.
- **Providers.** A provider with a custom base URL that relied on the
  `.env` key now needs its own key: enter it under Administration →
  Providers.

## Upgrading from 1.4.1

1. Take a backup ([deployment guide §5](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#5-backups)).
2. Check out the release and follow the usual upgrade steps
   ([guide §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.md#8-upgrading)):

   ```bash
   git fetch --tags && git checkout v1.4.2
   ```

   With Docker, `docker compose -f compose.production.yml up -d --build`.
   Without Docker, run `npm ci && npm run build`, then
   `php artisan migrate --force` and `php artisan optimize`. There are no
   new migrations.
3. **Without Docker:** copy `deploy/php-fpm/ada.conf` to the PHP-FPM pool
   directory again (it now sets `request_terminate_timeout = 420`) and
   restart PHP-FPM. If you raised `ADA_PROVIDER_TIMEOUT`, set the pool's
   timeout to that value plus 120 (Docker: `PHP_FPM_REQUEST_TERMINATE_TIMEOUT`).
4. If you use your own copy of the Docker nginx proxy file, add
   `proxy_set_header X-Forwarded-Prefix "";`.
5. Optional: set `ADA_SHARE_MAX_LINKS` and `ADA_SHARE_DAILY_LIMIT` in
   `.env` if the defaults (10 and 50) do not fit.
6. Run `php artisan ada:doctor`, and `composer audit` and `npm audit` on
   your checkout: dependency advisories were outside the audit's offline
   scope.

## Türkçe özet

Ada Chat 1.4.2 bir güvenlik sürümüdür. Tam güvenlik denetiminde bir orta
ve üç düşük seviyeli bulgu kesinleşti; sağlayıcı davranışına bağlı üç
olası sorun da bulundu. Hepsi testleriyle düzeltildi, denetimin
sağlamlaştırma önerileri de uygulandı. **Bütün kurulumların, özellikle
SAML ve OIDC girişini birlikte sunanların güncellemesi önerilir.**

- **Orta:** Bir e-posta adresi başkasına verildiğinde, diğer giriş
  yöntemiyle gelen yeni sahibi eski hesaba girebiliyordu. Artık e-postayla
  bağlama yalnızca kalıcı bir kimliğe bağlı olmayan hesaplarda yapılıyor;
  devre dışı hesaplar hiç bağlanmıyor.
- **Düşük:**
  - `.env` API anahtarı panelde girilen başka bir adrese gidebiliyordu;
    artık yalnızca sağlayıcının kendi adresine gidiyor.
  - Yöneticiler kendi grubu üzerinden kendi bütçelerini artırabiliyordu;
    kendilerinin ya da bir süper yöneticinin bulunduğu grubu artık
    yalnızca süper yönetici değiştirebiliyor.
  - Paylaşım sınırsızdı; artık sohbet başına 10 bağlantı, kullanıcı
    başına günde 50 bağlantı ve kopya sınırı var. İptal edilen bağlantının
    kopyası siliniyor.
- **Ücretlendirme ve erişilebilirlik:** Durdurulan Gemini ve OpenAI uyumlu
  akıl yürütme yanıtları gizli düşünmeyi de ödüyor; kullanım bilgisi
  gelmeyen yanıtlar girdiyi güvenlik payıyla ödüyor; PHP-FPM 420
  saniyeyi aşan istekleri sonlandırıyor.
- **Sağlamlaştırma:** Sağlayıcı istekleri yönlendirme izlemiyor, aşırı
  büyük akış verisi reddediliyor, `X-Forwarded-Prefix` yok sayılıyor,
  devre dışı kullanıcının paylaşımları kapanıyor, davet e-postasındaki
  adlar bağlantıya dönüşemiyor.

**Davranış değişiklikleri:** Kalıcı kimliğe bağlı bir hesap diğer giriş
yöntemiyle ilk kez girildiğinde `account_conflict` alır. Varsayılan grupta
süper yönetici varsa yöneticiler o grubu değiştiremez. Özel adresli ve
`.env` anahtarına dayanan sağlayıcılara kendi anahtarı girilmelidir.

**1.4.1'den yükseltme:**

1. Yedek alın, `git checkout v1.4.2` ile güncelleyin
   ([rehber §8](https://github.com/ardacetin/adachat/blob/main/docs/deployment.tr.md#8-güncelleme)).
   Yeni migration yok.
2. Docker: `docker compose -f compose.production.yml up -d --build`.
   Docker'sız: `npm ci && npm run build`, `php artisan optimize`, ayrıca
   `deploy/php-fpm/ada.conf` dosyasını yeniden kopyalayıp PHP-FPM'i
   yeniden başlatın.
3. Kendi nginx proxy dosyanızı kullanıyorsanız
   `proxy_set_header X-Forwarded-Prefix "";` ekleyin.
4. `php artisan ada:doctor`, `composer audit` ve `npm audit` çalıştırın.
