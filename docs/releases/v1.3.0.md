# Ada Chat 1.3.0

> Released 2026-10-02 · [Türkçe özet aşağıda](#türkçe-özet)

The third feature release, chosen with the pilot. Answers can now draw on
the web through the providers' own search tools, users are warned before
their budget runs out, answers can be rated without revealing anything to
administrators, and conversations can be shared with colleagues as
read-only copies. Everything was built in five steps, each with tests,
documentation and review ([roadmap](../v1-roadmap.md#v13)).

## Highlights

- **Web search.** When an administrator allows it on a model alias, users
  turn on "Web search" for a message
  ([provider-architecture.md §10](../provider-architecture.md#10-web-search)).
  - Ada uses each provider's own search tool: Anthropic web search and
    OpenAI web search. Gemini (Grounding with Google Search) is supported
    but switched off in the catalog, see below.
  - The chat shows each search while the answer streams and lists the cited
    pages under the answer, numbered, opening in a new tab. The Markdown
    export includes them.
  - Models have a search capability and a price per 1,000 searches (catalog:
    $10 for Anthropic and OpenAI). Aliases allow up to 5 searches per
    message. Assistants have their own switch.
  - The budget reserves the allowed searches before the message and charges
    the searches the provider billed. Reports and their CSV count web
    searches and their cost.
  - Ada stores only the cited pages (address and title), not the search
    queries or the page contents.
- **Budget alerts for users.**
  ([budget-engine.md §7.6](../budget-engine.md#76-user-budget-alerts-v13)).
  - At 80 % of the monthly budget the chat shows a warning until the user
    closes it.
  - Users get an e-mail at 80 % and at 100 %, once per month each, in
    their own language.
  - Users can turn the e-mails off in Settings → Notifications;
    administrators can turn them off for everyone in Admin → Institution.
  - Raising a user's limit re-arms a threshold that was already announced.
- **Answer feedback.** Every finished answer has 👍 and 👎; a thumbs down
  asks for a reason from a fixed list (no free text)
  ([docs/feedback.md](../feedback.md)).
  - Admin → Satisfaction shows the votes, the share of thumbs up and the
    reasons, by model alias, model or assistant, from 5 votes on.
  - Votes are stored without the user. When a conversation is deleted, its
    votes remain only as anonymous counts.
- **Conversation sharing.** The owner of a conversation creates a
  read-only link ([docs/sharing.md](../sharing.md)).
  - The link shows the conversation as it was at that moment. Later
    messages never appear.
  - Only signed-in, active users of the installation can open it.
  - Attached files appear by name only and are never served through a
    link.
  - Viewers can copy the conversation into their own and continue it; the
    model is kept only where they may use it.
  - Owners see their live links with view counts and can revoke them.
    Deleting the conversation also stops its links.
  - Admin → Institution → Sharing turns the feature off, which stops every
    existing link.
  - Only a hash of each link's token is stored. Administrators get no list
    of shares.

The full list is in the [changelog](../../CHANGELOG.md#130---2026-10-02).

## Requirements

Unchanged from 1.2.0 (see the [1.0.0 notes](v1.0.0.md#requirements)).

- Budget e-mails need a working mailer (`MAIL_*`), as the cap alerts and
  the monthly report already do. Without one they are written to the log.
- The scheduler must run (it already must, see
  [deployment guide](../deployment.md)). It now also runs
  `ada:budget:user-alerts` every five minutes.

## Upgrading from 1.2.0

1. Take a backup ([deployment guide §5](../deployment.md#5-backups)).
2. Check out the release and follow the usual upgrade steps
   ([guide §8](../deployment.md#8-upgrading)):

   ```bash
   git fetch --tags && git checkout v1.3.0
   ```

   With Docker, `docker compose -f compose.production.yml up -d --build`
   rebuilds the image and runs the migrations on start. Without Docker,
   run `php artisan migrate --force`. The migrations add:
   - web search to models, aliases, assistants and usage records;
   - budget alert markers to budget periods, and the e-mail switch to
     users;
   - the `message_feedback` and `conversation_shares` tables;
   - two settings: `institution.user_budget_emails` and
     `institution.conversation_sharing`, both on.

   Settings are cached; migrations now clear that cache themselves. Older
   versions needed `php artisan cache:clear` after an upgrade; it does no
   harm.
3. **Web search prices.** Catalog models added before 1.3 show the "New
   catalog prices" badge in Admin → Models, because the catalog now has
   a search price for them. "Use new prices" takes the price over
   (audited). After that, the model can search.

   Then allow search on the aliases that should have it (Admin → Model
   aliases → "Web search", with the maximum searches per message). For
   assistants, also turn it on in the assistant.

   Models outside the catalog get search only when you mark them as
   searching and enter a price per 1,000 searches yourself.
4. **Gemini.** Google's Gemini API terms require Google's Search
   Suggestions to be shown with every answer grounded in Google Search.
   Ada does not show them yet, so the catalog lists Gemini models without
   web search. Do not turn search on for Gemini models by hand unless you
   have checked those terms for your use.
5. **Budget e-mails.** They are on. To turn them off for everyone, clear
   "E-mail users at 80 % and 100 %…" in Admin → Institution.
6. **Sharing.** It is on. To keep it off, clear "Allow users to share
   conversations" in Admin → Institution → Sharing.
7. Optional `.env` value: `ADA_WEB_SEARCH_RESERVE_TOKENS` (4000). It sets
   the input tokens the budget reserves per allowed search for the pages a
   search adds to the context.
8. Run `php artisan ada:doctor`. It warns about an alias that allows search
   on a model that cannot search or has no search price.

## Known limitations

- One institution per installation; no public API yet.
- Conversation content, attached files, assistant documents and the
  snapshots of shared conversations are stored unencrypted. Anyone with
  server or backup access can read them; protect them accordingly
  ([security.md](../security.md)).
- Gemini web search is off until Ada shows Google's Search Suggestions.
- Web search uses the basic tools. When Anthropic pauses a turn during its
  searches, the answer ends with "The answer reached its length limit." and
  is not continued automatically.
- A shared link shows a snapshot. To share a later state of the
  conversation, create a new link. Copies do not include attached files
  or the assistant.
- Budget e-mails are sent by the scheduler within five minutes of the
  threshold, not at once.
- No RAG over large document collections, no OCR, no legacy Office
  formats, no tools or agents beyond web search.

## Türkçe özet

Ada Chat 1.3.0, pilotla birlikte seçilen üçüncü özellik sürümüdür.

- **Web araması:** Yönetici bir model takma adında izin verirse kullanıcı
  mesaj başına "Web araması"nı açar.
  - Sağlayıcıların kendi arama araçları kullanılır: Anthropic ve OpenAI.
  - Sohbet, yanıt gelirken yapılan aramaları ve yanıtın altında
    kaynakları gösterir.
  - Arama fiyatı bütçeden düşülür; raporlar aramaları sayar.
  - Ada yalnızca alıntılanan sayfaların adresini ve başlığını saklar.
  - Gemini'de arama kapalıdır (Google'ın Search Suggestions şartı).
- **Kullanıcılara bütçe uyarısı:**
  - Bütçenin %80'inde sohbette bir uyarı görünür.
  - %80'de ve %100'de kullanıcının kendi dilinde e-posta gider.
  - Kullanıcı e-postaları Ayarlar → Bildirimler'den kapatabilir; yönetici
    herkes için Yönetim → Kurum'dan kapatabilir.
- **Yanıt geri bildirimi:**
  - Her yanıtta 👍 / 👎 var; 👎 sabit bir listeden sebep sorar.
  - Yönetim → Memnuniyet ekranı oyları takma ad, model ve asistana göre
    gösterir.
  - Oylar kullanıcı bilgisi olmadan saklanır.
- **Sohbet paylaşımı:**
  - Sohbet sahibi salt okunur bir bağlantı oluşturur. Bağlantı, sohbetin
    o anki kopyasını yalnızca oturum açmış kullanıcılara gösterir.
  - Ekler yalnızca adlarıyla görünür.
  - Görüntüleyen kişi sohbeti kendi sohbetlerine kopyalayabilir.
  - Bağlantılar iptal edilebilir. Yönetim → Kurum → Paylaşım kapatılırsa
    bütün bağlantılar durur.

**1.2.0'dan yükseltme:**

1. Yedek alın.
2. `git checkout v1.3.0` ile güncelleyin
   ([rehber §8](../deployment.tr.md#8-güncelleme)). Docker migration'ları
   kendisi çalıştırır; Docker'sız kurulumda `php artisan migrate --force`
   çalıştırın. Ayar önbelleği artık migration'dan sonra kendiliğinden
   temizlenir.
3. 1.3'ten önce eklenen katalog modelleri Yönetim → Modeller'de "Yeni
   katalog fiyatları" rozetiyle görünür. "Yeni fiyatları kullan" arama
   fiyatını alır ve aramayı mümkün kılar. Ardından aramanın açık olacağı
   takma adlarda (ve asistanlarda) aramayı açın.
4. Gemini modellerinde aramayı elle açmayın (Google şartları).
5. Bütçe e-postaları ve sohbet paylaşımı açık gelir. İstemiyorsanız
   Yönetim → Kurum'dan kapatın.
6. Zamanlayıcı artık `ada:budget:user-alerts` komutunu da çalıştırır;
   zamanlayıcının çalıştığından emin olun.
7. `php artisan ada:doctor` çalıştırın.

**Bilinen sınırlamalar:**

- Kurulum başına tek kurum; henüz dış API yok.
- Sohbetler, ekler, asistan belgeleri ve paylaşılan sohbet kopyaları
  sunucuda şifresiz durur.
- Gemini'de web araması kapalıdır.
- Paylaşılan bağlantı bir anlık kopyadır.
- Bütçe e-postaları zamanlayıcıyla en geç beş dakika içinde gider.
- RAG, OCR, eski Office biçimleri ve web araması dışında araç yok.
